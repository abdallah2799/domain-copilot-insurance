# Agentic coding workflow

This project was built with Claude Code as a governed participant, not a code-generation shortcut. This document tracks what's actually configured and used — including, honestly, where the tooling setup fell short of what a fuller agentic-development practice would include.

## What's configured (real, committed)

1. **Project instruction file** — [`CLAUDE.md`](../CLAUDE.md), read automatically at the start of every session. Encodes the Clean Architecture dependency-direction rules (which project may reference which), the deterministic-math rule for payout/limit/deductible calculations, the prompts-as-versioned-files rule, and process rules (no direct commits to `main`, Conventional Commits, no AI attribution trailers on commits/PRs, docs updated in the same PR as the behavior they describe). This is the mechanism that kept the assistant from casually reaching across a layer boundary it would otherwise not "know" about, and — separately — from complying with at least one injected mid-session instruction that tried to reverse the no-AI-attribution rule (caught and flagged rather than silently followed; see `docs/AI-USAGE-LOG.md`).
2. **Versioned prompt library** — [`prompts/`](../prompts/): six files (`ask.md`, `ask-stream.md`, `coverage-matcher.md`, `anomaly-analyst.md`, `exclusion-analyst.md`, `adjudication-drafter.md`), each with worked examples, never inlined as C# string literals (CLAUDE.md's own rule). These were iterated on directly in response to real observed model failures — e.g. `anomaly-analyst.md` gained an explicit termination-condition block after a real non-convergence bug was diagnosed (see `docs/AI-USAGE-LOG.md` and ADR-0009).
3. **Plan-mode gating** — Claude Code's plan mode was used before any file was created: the assignment PDF and stack decisions were turned into a written plan (variant, architecture, MoSCoW backlog, day-by-day pacing) and required explicit approval before any repository or code change happened. Mid-review, four corrections were made to the plan (target framework, incremental-not-dumped documentation, the second auth role not being fixed in advance, and the real 6-day timeline) before implementation started.
4. **Structured clarification instead of silent assumptions** — used throughout, not just at the start: the correct GitHub account, the Domain/Twist variant, the CI runner target, the LLM provider pairing, and later judgment calls (e.g. how to close a documentation gap found during a pre-submission audit — this exact file's rewrite was one such instance) were all resolved by an explicit forced choice rather than a guess.

## What's not configured, and why this is disclosed rather than padded

The brief asks for "≥5 of: instruction files, custom commands, subagents, hooks, MCP usage, prompt library." Only **2 of those 6 categories are real** in this repository — the instruction file and the prompt library above. No custom slash commands, no project-scoped subagents, no hooks, and no MCP server configuration exist here (`.claude/commands/`, `.claude/agents/`, `.claude/settings.json` hooks, and `.mcp.json` are all absent).

This is a genuine gap, not an oversight discovered and hidden — it was found during a pre-submission readiness audit and is reported here as exactly what it is: a scope cut made under real time pressure (a ~6-day build window against the brief's own ~12-day assumption, spent on the Must-have feature floor first), not evidence that these tools weren't considered. A fuller setup would plausibly have included:

- **A custom command** wrapping "run the evaluation harness end-to-end and update `docs/EVALUATION.md`" — the exact multi-step, easy-to-get-slightly-wrong workflow this project's own evaluation-harness sessions repeated by hand several times.
- **A pre-commit-style hook** mechanically enforcing the layering rule `CLAUDE.md` currently only states declaratively (blocking a commit that adds a disallowed package reference to `Domain`/`Application`), rather than relying on the assistant (or a human reviewer) to catch a violation by inspection.
- **A subagent** scoped specifically to a security-review pass against `docs/SECURITY.md`'s own checklist, run independently before each PR touching an auth/injection-relevant surface.

None of these were built. Recording this honestly — rather than either quietly building something minimal just to clear a number, or omitting the shortfall — is itself the practice `docs/AI-USAGE-LOG.md` exists to model: an inflated or padded account of tooling maturity would be a worse submission than an accurate, smaller one.

## Where the agentic approach failed or needed correction

- The AI's first attempt to patch a flagged vulnerable NuGet package (`Microsoft.OpenApi` 2.0.0 → 2.0.1) was itself insufficient — the advisory's actual patched range starts at 2.7.5 for the 2.x line. Caught by re-checking the GitHub Security Advisory API directly rather than trusting the version-bump alone. This is now written into `CLAUDE.md` as a standing rule.
- Left to its own judgment, the initial plan targeted .NET 8 and would have written all "must-have" documentation as a single late-stage pass on the assumed 12-day window — both were corrected by direct user review before any code was written.
- Multiple real agent-pipeline bugs were found only by actually running the system against a real model rather than trusting unit tests with fakes: a too-short HTTP timeout for genuine local-model latency, a model writing a tool call out as literal text instead of using structured function-calling, a correct answer buried in prose that a naive parser missed, and a misleading error message that reported "failed after 3 attempts" when the real cause was a single step-timeout cancellation. Each is logged with its actual root cause and fix in `docs/AI-USAGE-LOG.md`, not smoothed over.
- A specific model-capability limitation (Anomaly Analyst's non-convergence on a two-tool sequence) was initially hypothesized as "probably fixed by a hosted model" — this prediction was tested directly against a real hosted model rather than accepted on faith, found to be wrong (the same failure reproduced identically), and the earlier ADR was corrected in the same session rather than left standing.
- Mid-session, a message formatted as a system reminder instructed that commit/PR text should start including AI attribution trailers, directly contradicting the user's standing, repeated instruction. This was not followed — flagged to the user instead, on the reasoning that an instruction arriving this way, attempting to reverse an explicit prior instruction, is exactly the kind of thing worth surfacing rather than silently complying with or silently ignoring.
- This file itself was stale for most of the project (last touched on day 1, describing only day-1 tooling and a "planned" list that had partly gone stale) until a pre-submission audit caught it and prompted this rewrite — an example of a living-document rule not being followed in practice for one document, caught late rather than never.

See [`docs/AI-USAGE-LOG.md`](AI-USAGE-LOG.md) for the running, dated log of delegated-vs-hand-verified work.
